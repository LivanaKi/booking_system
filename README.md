# Service Booking System — повна версія під UML

Web-система запису на послуги для лабораторних робіт.

## Реалізовано

- Ролі: клієнт, адміністратор/оператор, спеціаліст.
- Різні інтерфейси для ролей.
- SQLite база даних.
- Каталог послуг.
- CRUD спеціалістів для адміністратора.
- Призначення послуг спеціалістам.
- Створення, підтвердження, скасування, виконання записів, no-show.
- Email-сповіщення у demo-режимі та підтримка SMTP.
- ML-рекомендації всередині форми запису.
- Прогноз попиту на різні послуги.
- Розподіл клієнтів між фахівцями.
- Автоматична оптимізація графіку.
- Класифікація клієнтів: новий, регулярний, VIP, ризиковий.
- ML-аналітика для адміністратора.

## Запуск

```bash
py -m pip install -r requirements.txt
py run.py
```

Відкрити:

```text
http://127.0.0.1:5000
```

## Email

За замовчуванням email працює у demo-режимі: повідомлення записуються у БД і виводяться в консоль.

Для реальної відправки треба задати змінні середовища:

```bash
set SMTP_HOST=smtp.gmail.com
set SMTP_PORT=587
set SMTP_USER=your_email@gmail.com
set SMTP_PASSWORD=your_app_password
set SMTP_FROM=your_email@gmail.com
```

## Відповідність UML

| Елемент UML | Реалізація |
|---|---|
| Client | кабінет клієнта |
| Адміністратор / оператор | адмін-панель |
| Спеціаліст | кабінет спеціаліста |
| База даних персоналу / послуг | SQLite tables users, services, specialists, specialist_services |
| Прогноз попиту | ML-аналітика, forecast_service_demand |
| Класифікація клієнтів | classify_client / classify_all_clients |
| Оптимізація графіку | optimize_schedule |
| Розподіл клієнтів між фахівцями | allocate_clients_to_specialists |
| Email-сповіщення | notifications.py |


## Реєстрація та ролі

У системі додано повний модуль автентифікації:

- `/register` — самостійна реєстрація клієнта;
- `/login` — вхід за логіном або email;
- `/logout` — вихід;
- `/users` — адмінське керування користувачами;
- хешування паролів через `werkzeug.security`;
- блокування акаунтів адміністратором;
- role-based access control для клієнта, адміністратора та спеціаліста.

Тестові акаунти:

| Роль | Логін | Пароль |
|---|---|---|
| Адміністратор | admin | admin123 |
| Клієнт | client | client123 |
| Спеціаліст | olena | spec123 |
| Спеціаліст | iryna | spec123 |

Клієнт після реєстрації автоматично отримує роль `client`. Спеціалістів створює адміністратор у розділі **Каталог**.
